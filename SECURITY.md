# Security and scope

This is a single-owner self-hosted tool, not a hosted service, multi-tenant product or audited authentication vault. Every configured reader can retrieve **any** matching captured code or approved sign-in link. Separate keys isolate claim ownership and revocation, not mailbox permissions.

Phone and mailbox keys are write-only. Agent keys can list and claim. Gmail is read-only, but that scope technically permits reading the whole mailbox; the code searches recent OTP-like messages. The backend and chosen agent providers process secrets. HTTPS is required outside localhost. There is no end-to-end encryption between a phone and an agent.

## Main limits

- Keep one replica, always running. Memory is cleared on restart. Claims are not durable; startup can reload a still-valid email that was claimed before restart.
- Entries expire within ten minutes or recognized shorter validity. Optional Postgres audit history retains service, recipient account, capture method, receipt/expiry times, configured client name and outcome until the owner deletes it. It has no message text, preview, sender, OTP, sign-in URL, credentials or code hash. All reader keys can read this history, just as they can read the inbox. Retrieval records mean the bridge approved secret release; they do not prove delivery, successful authentication, the human behind a client or the originating task. Shared reader keys cannot distinguish individual tasks. Restarts still reset live claim ownership; history does not restore it. Original SMS and Gmail mail remain. Provider logs and agent histories have their own retention policies. Expiry here cannot erase a code already shared with an agent.
- Phone delivery has no durable queue. Android background limits, network failure and iOS permissions can lose delivery. Gmail push can be delayed or dropped. Keep minute polling as backup and to renew watch leases daily.
- Search reads at most 50 recent matching emails per scan, excludes Spam/Trash/sent-only mail, and can miss unfamiliar wording. This is not universal mail coverage.
- Service labels, sender names and message bodies can be spoofed. Match an authorized login's time, account and service. Ambiguous tokens are not guessed. Available email links additionally require an exact configured sender and HTTPS destination plus a Gmail-authenticated matching sender domain; this cannot rule out a compromised sender.
- No persistent rate-limit store. Use an HTTPS proxy with request rate limits for internet hosting; never expose internal app logs containing request bodies. The application caps body and entry sizes, not sustained distributed traffic.
- Android guide is untested on physical hardware. The portable public setup and HTTP MCP have local synthetic tests; these are separate from earlier real iPhone/Gmail/agent tests of the private predecessor.

## Optional SMS AI observation

Core capture and filling require no AI provider. An owner can enable [SMS observation](docs/sms-observation.md), which sends whole fresh authenticated SMS text to OpenAI for classification/extraction, including messages the current parser rejects. It never sends email to this model and cannot change entries, claims or autofill. The bridge exposes aggregate comparisons only; private duplicate hashes expire after ten minutes. Responses use `store:false`, but provider abuse-monitoring retention can still apply. With an owner-configured `OTP_AI_OPENROUTER_KEY`, OpenAI funding errors send the same AI request to OpenRouter and its upstream model using strict structured output and explicit privacy-routing preferences. OpenAI is retried on the next request after five minutes. OpenRouter account and upstream safety-retention rules still apply; this is not a blanket zero-retention guarantee. Model uncertainty does not trigger another provider. New installations default off. The maintainer pilot has explicitly enabled it. Request limits reset on process restart and are not a hard billing cap.

## Secrets and revocation

Everything generated by setup is under ignored `.local/`, mode 600 where supported. Never commit that folder, customized Shortcuts, Apps Script projects, OAuth downloads, environment files or screenshots of codes. Do not put client/source keys in URLs. Service-issued login links are secrets: never log, preview-fetch, screenshot or persist them. List/wait hide the entire link; only a selected claim returns it. A phone shortcut contains its write-only key and may sync through iCloud.

To stop capture, disable phone automation and Apps Script triggers, then revoke the Google app in Account connections. Revoke refresh tokens and remove them from hosting. The Chrome helper saves its dedicated reader key in extension local storage restricted to trusted extension contexts. The connection survives Chrome restarts and extension reloads; Disconnect removes the key and seen-item history. It is not synced or shared with web pages/content scripts. This is local browser profile storage, not an OS keychain or encrypted vault: someone who controls the profile or extension developer tools can access the key. It requests network access to the selected bridge host and uses activeTab for manual filling. Optional automatic login filling requests all-HTTPS website access once, or site-only access for custom rules. Global mode derives the website brand with a public/private suffix parser and matches one fresh SMS or email item; custom rules can bind service/channel/account. A site opt-out overrides global mode. It checks the selected tab, empty login fields, fresh code and exact originating document; recognized recovery contexts stay manual. Payment automation is a separate saved owner choice: fill only, or fill and click one clear confirmation button scoped to the OTP form. Payment mode requires an issuer match in message metadata and rechecks page purpose before writing; filling alone may authorize a charge on some bank pages. The default is off; no real charge is used for automated QA. Content scripts cannot read the saved reader key. Site disable saves an opt-out and removes its specific host grant; global-off keeps the website grant but stops global filling; Disconnect removes all such rules and grants. All readers still have deployment-wide inbox access; the helper is not a narrower server role.

To revoke an agent, remove its key from server configuration and redeploy. Restart clears transient copies but may reload recent Gmail unless that capture source is disabled.

If a secret was published, revoke it first; deleting the Git file does not remove Git history. Avoid posting vulnerabilities or private messages in public issues. Use GitHub's private security advisory reporting when enabled, or contact the maintainer through the GitHub profile without sending live credentials.

OTP access does not authorize purchases, payments, security changes or sharing codes with other people. This project does not bypass an agent's approval policy.
